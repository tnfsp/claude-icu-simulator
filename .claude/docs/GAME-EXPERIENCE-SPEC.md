> 2026-03-24 從 Owl + Wilson 討論中提煉。所有模式（Standard/Pro）共用的體驗設計原則。

## 核心問題

**現在的系統是「介面」，不是「體驗」。**

打開 → 看數字 → 點按鈕 → 看結果 → 交卷。沒有敘事弧線、沒有情緒起伏、沒有不確定性。

---

## 真實 ICU 被 Call 的七步體驗

模擬器應該重現這個體驗弧線：

| # | 階段 | 真實體驗 | 目前系統 | 設計目標 |
|---|------|---------|---------|---------|
| 1 | **電話響** | 不知道多嚴重，心裡開始跑 differential | ✅ 有（護理師 call） | 護理師描述要模糊、不完整 |
| 2 | **走到床邊** | 第一眼看臉色、呼吸、monitor 波形，直覺判斷 | ❌ 缺 | 需要視覺衝擊 — 波形、病人外觀 |
| 3 | **資訊碎片化** | 護理師講一半被打斷、lab 沒回、echo 要借 | ❌ 缺 | 資訊不一次給完，要主動獲取 |
| 4 | **壓力遞增** | 病人在變差，護理師在等你下 order | ❌ 缺 | 時間壓力 + 護理師催促 |
| 5 | **做決定** | 不確定對不對，但必須做 | ⚠️ 有但無重量 | 決策有後果，vitals 會變 |
| 6 | **等待結果** | 盯著 monitor 看有沒有改善 | ❌ 缺 | 開藥後要等，看 vitals 漸變 |
| 7 | **收尾或崩盤** | 穩住交班 / 惡化叫人 | ⚠️ 部分 | 交班 + escalation 路徑 |

## 設計原則

### 1. 遊戲中不教學

> **教學是完成之後的事情。**

- 遊戲中只給**真實會有的資訊**：護理師回報、monitor 變化、lab 結果
- 不要在 order 旁邊顯示「為什麼」
- 不要即時告訴玩家做對或做錯
- **後果本身就是教學** — 開錯藥 → vitals 惡化，這就是最好的 feedback
- 所有教學內容放在 **Debrief**（遊戲結束後）

### 2. 護理師是核心角色（Claude 驅動）

護理師不是腳本化的觸發訊息，是**有個性的 AI 角色**：

| 情境 | 護理師反應 |
|------|----------|
| 開 NS bolus 但 JVP 高 | 「學長，這個 patient JVP 蠻高的欸，確定要 bolus 嗎？」 |
| 猶豫太久 | 「學長，BP 又掉了，要不要先掛個什麼？」 |
| 開抗生素沒抽 culture | 「那 blood culture 要不要先抽？」 |
| 下了合理 order | 「好，我馬上掛」（簡潔） |
| 同時開 fluid + diuretic | 「學長，這兩個會不會衝突啊？」 |

**設計要點**：
- 護理師 = 安全網 + 壓力源
- 不直接說「你錯了」，但會用臨床常見的方式暗示（「確定嗎？」「蛤？」）
- 有自己的節奏 — 不是即時回應，有時候忙別床會晚回
- 用 Claude API 驅動，給予 scenario context + 玩家行為

### 3. 資訊碎片化 — 不一次給完

| 資訊 | 取得方式 | 等待時間 |
|------|---------|---------|
| Vital Signs | 自動顯示 | 即時 |
| 病史 | 要問護理師/問病人 | 即時 |
| 理學檢查 | 要主動做 | 即時 |
| Lab 結果 | 開立後等待 | 30-90 秒（模擬真實） |
| POCUS | 要主動做 | 即時 |
| 影像（CXR） | 要 order | 2-3 分鐘 |
| 學長意見 | 要打電話 | 看報告品質決定回應 |

### 4. 節奏感 — 安靜與緊張交替

- **安靜時刻**：等 lab、等藥物作用、觀察 vitals 趨勢
- **緊張時刻**：突然惡化、護理師急 call、vitals 跳警報
- 不是平的一條線 — 有起伏
- 靜默不代表安全，有時候安靜反而更可怕（「學長…病人好像沒有呼吸了」）

### 5. Fog of War — 資料不完美

- Troponin 可能是 4 小時前的舊值
- SpO2 probe 接觸不良顯示 88%（其實正常）
- 護理師記錄的 BP 跟你自己量的不一樣
- 某些 lab 結果有 hemolysis 影響（K+ 偏高但不是真的）
- **讓玩家學會判斷資料品質**，不是盲信數字

### 6. Escalation 路徑

| 選項 | 學長回應 | 設計目的 |
|------|---------|---------|
| 電話報告品質好 | 給指導、說「你先處理，我等下來看」 | 鼓勵完整報告 |
| 電話報告太差 | 「你先講清楚，這病人怎樣？」 | 訓練溝通 |
| 太早 call | 「你先自己看一下再打來」 | 鼓勵獨立思考 |
| 太晚 call（病人快不行了） | 「怎麼現在才打！我馬上下來」 | 學會判斷時機 |

學長也用 Claude 驅動。

## 模式差異

### Standard Mode（Clerk / 非醫護）

- 護理師提示更多（不是教學，是真實護理師會對 junior 說的話）
- Fog of war 較少（資料較乾淨）
- 惡化速度較慢（給更多思考時間）
- Debrief 更詳細（有 guided review）
- 干擾選項較少（3-4 個正確 + 1-2 個干擾）

### Pro Mode（R 以上）

- 護理師不主動提示（你要問她才回答）
- 完整 fog of war
- 惡化速度快
- Debrief 簡潔（只列關鍵 decision points）
- 更多干擾選項（2-3 個正確 + 3-4 個干擾 + trade-off 選擇）
- ACLS scenario 可觸發

## 非醫護玩家考量

> 此系統也可能給護理系學生、EMT、甚至對醫學有興趣的一般人使用。

### 適配策略

| 層面 | 非醫護適配 |
|------|----------|
| 術語 | 關鍵醫學術語附簡短中文說明（如 hover tooltip） |
| 選項 | 每個醫囑選項附一行白話描述（不是教學，是 context） |
| 護理師 | 更口語化，會用白話解釋病人狀況 |
| Debrief | 增加「背景知識」區塊，解釋為什麼某些處置重要 |
| 難度 | 可選「學習模式」— 惡化更慢、提示更多、失敗後可繼續不 Game Over |

### 不做的事

- 不把遊戲變成教科書 — 核心還是體驗
- 不降低醫學準確性 — 簡化解釋但不扭曲事實
- 不在遊戲中教基礎知識 — 那是教科書的工作

## 體驗目標

### 玩完之後的感受

**Clerk**：「原來 ICU 被 call 是這種感覺。我下次去 ICU 值班前要先想清楚 cardiogenic shock 跟 septic shock 怎麼分。」

**R**：「這個 case 我開錯藥了，原來 NE 在 LV failure 不是首選。護理師那句『JVP 蠻高的欸』我應該要注意到的。」

**非醫護**：「原來醫師在 ICU 面對的壓力是這樣。要在不確定的情況下做決定好難。」
